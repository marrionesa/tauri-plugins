# Tauri v2 Plugin Workspace

Six standalone [Tauri v2](https://v2.tauri.app) plugins, each one publishable
independently to **crates.io** and **npm**.

Every plugin follows the conventions the Tauri team uses for its own
[`tauri-apps/plugins-workspace`](https://github.com/tauri-apps/plugins-workspace)
monorepo (branch `v2`), so any of them is submission-ready for upstream review:

- Dual `Apache-2.0 OR MIT` license, with SPDX headers on every Rust file.
- `tauri-plugin-<name>` crate name, `@marrionesa/plugin-<name>` npm package.
- `tauri::plugin::Builder::new("<name>").invoke_handler(...).build()` entry point.
- `build.rs` declares its commands, so `permissions/autogenerated/` is generated
  on every build and `allow-<command>` / `deny-<command>` identifiers exist.
- `[package.metadata.platforms.support]` block declaring per-platform support.
- CI: `fmt.yml`, `lint-rust.yml`, `test-rust.yml` (+ optional `mirror.yml`).
- Covector-driven dual publish, with the Rust and JS versions kept in lockstep.

| `tauri-plugin-timezone` | `get_timezone`, `get_utc_offset_seconds` | all                                            | `@marrionesa/plugin-timezone` | `tauri-plugin-timezone` |

Each plugin's `README.md` documents installation, the permission table, and the
full JavaScript API. Each `CHANGELOG.md` records what shipped in `0.1.0`.

## Layout

```
tauri-plugins/
├── _TEMPLATE/                 # copy-and-rename scaffold for a new plugin
├── tauri-plugin-beep/         # one directory per plugin, each self-contained
├── tauri-plugin-hash/
├── tauri-plugin-hostname/
├── tauri-plugin-mimetype/
├── tauri-plugin-timezone/
├── tauri-plugin-uuid/
├── Cargo.toml                 # Rust workspace (one lock file, shared tooling)
├── package.json               # pnpm workspace root (prettier)
├── .github/workflows/         # CI: fmt, lint-rust, test-rust, mirror
├── .changes/                  # covector config + change files
└── CONTRIBUTING.md, CODE_OF_CONDUCT.md, SECURITY.md
```

The plugin directories are the unit of publishing: each contains a complete,
self-contained crate **and** npm package. The root `Cargo.toml` exists only so
that `cargo fmt --all`, `cargo clippy --workspace` and a single `Cargo.lock`
work in CI; it is never published.

## Scaffolding a new plugin from the template

```bash
# 1. Copy the template
cp -r _TEMPLATE tauri-plugin-<name>

# 2. Rename the placeholders
#    - crate name:            tauri-plugin-template  -> tauri-plugin-<name>
#    - npm package:           @marrionesa/plugin-template -> @marrionesa/plugin-<name>
#    - plugin name (Builder): "template"              -> "<name>"
#    - android package:       com.plugin.template     -> com.plugin.<name_snake>
#    - Swift target:          tauri-plugin-template   -> tauri-plugin-<name>
#    - COMMANDS in build.rs:  ["ping"]                -> your actual commands
#    - add the crate to `members` in the root Cargo.toml

# 3. Build both halves
cd tauri-plugin-<name>
cargo build --release
npm install && npm run build
```

## Quality gates

Everything CI enforces can be run locally, from the repository root:

```bash
cargo fmt --all -- --check                              # rustfmt
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace                                  # unit tests
npx prettier --check .                                  # JS/TS/MD/YAML
npx @taplo/cli@0.5.2 fmt --check                        # TOML
```

Per plugin, the packaging checks are:

```bash
cargo publish --dry-run   # inside the plugin dir
npm pack --dry-run        # inside the plugin dir
```

## Publishing

Publishing is **manual** on purpose: nothing in this repository pushes to
crates.io, npm or any git remote. See
[`INFORME-PUBLICACION.md`](./INFORME-PUBLICACION.md) for the exact, ordered
commands for both registries.

The two halves of a plugin must always be released with the **same version**:
bump the Rust crate and the npm package together, and add a `.changes/` entry
listing both (`tauri-plugin-<name>` and `tauri-plugin-<name>-js`).
